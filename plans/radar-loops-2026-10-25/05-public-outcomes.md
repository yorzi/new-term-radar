# 05 · 公开结果 → 证据案例 → 决策使用

[返回总览](README.md) · Atlas 26/30；17/24/27/29 为辅助。第五类是条件性学习/内容闭环，优先级最低，不以近期收入为承诺。

## 为什么留下，又为什么不能高估

前四类会自然积累迁移、维护、自动化和用户采纳的结果。将这些材料整理为“什么条件下该做、什么情况下不该做”，可帮助自己和其他工程型创业者避免重复错误。但信息整理很容易退化为失败故事消费，且已有 Failory 等免费内容替代。[C01](sources.md)

真正差异只能来自可核查时间线、反例和明确决策用途，而不是更多故事或 AI 摘要。首轮读者收窄为在做 Ruby/Rails 小产品和产品化服务的独立开发者；不面向所有创业者做失败百科。

潜在付费研究买方与免费读者是不同人群。本轮没有机构研究客户证据，故不建设订阅数据库、不估算 TAM、不承诺广告变现。

## 案例采集规范

优先创始人/公司官方复盘、关停公告、公开 issue/release 时间线；第三方文章用于发现线索。一次官方关停公告足以证明“宣布了关停”，但不足以证明唯一原因。

每条陈述采用两层标记：

- **来源层**：官方记录、当事人自述、第三方分析、无法核实。
- **结论层**：观察事实、作者解释、我们的推断、未知。

同一句话可能是“一手自述 + 未独立验证的原因”，不能因为一手就全部当客观因果。创始人回忆也可能有幸存偏差、事后合理化和遗漏。

## 最小案例卡

| 字段 | 写法 |
|---|---|
| 项目与状态 | shutdown / sunset-feature / paused / acquired / pivot / unknown；明确业务范围 |
| 时间线 | 公告日、行动日、导出截止、后续更新；注明时区和来源 |
| 原始假设 | 只有当事人明确表达时才填写，不从失败结果反推最初动机 |
| 用户与任务 | 可见的目标人群及其需要完成的工作；未知留空 |
| 收入/成本 | 仅有可引用披露时记录，标币种、周期、毛/净额和自述性质 |
| 原因解释 | 每个解释绑定来源，允许互相冲突，不强制归为一个标签 |
| 反例与替代解释 | 类似产品仍成功的条件、分发/团队/时点等无法控制的变量 |
| 对当前决策的用处 | 一条可验证的问题或停止条件，不写普遍成功法则 |
| 更正 | 原链接、核查日、修订记录和更正入口；无须保存无关个人信息 |

## 一份已核查的示例：Glitch hosting 退出

事实：Glitch 官方于 2025-05-22 公告，project hosting 和用户 profile 将于 2025-07-08 关闭，并说明当时的导出安排。[S07](sources.md)

分类应为 `sunset-feature/service`，不能仅凭这一公告写成“Glitch 公司破产”或“创始人失败”。公告表达对生态变化的解释，但本轮没有财务核验，不能断言成本或竞争是唯一原因。

可迁移的决策问题：依赖平台时，是否有独立导出、域名/重定向和迁移窗口方案？这是由该事件启发的设计问题，不是“所有托管业务都会失败”的结论。

本案例今天只适合历史研究和反例训练，不属于当前可销售迁移线索。原公告的导出期限不能当作当前服务保证。

## 从研究到反馈

1. **设一个问题**：例如“基础设施依赖变动时，小团队遗漏了什么退出安排？”不要先抓 100 个故事再找主题。
2. **最多选择 3 个案例**：至少一个结果不同的对照；如果只有失败样本，只能描述，不能估算失败概率。
3. **抽取证据**：逐条事实指向原文，短引与概述为主，不镜像全文或复制整库。
4. **形成一个决策工具**：例如迁移前核对表、停止条件对照，而不是模糊的“重视用户”。
5. **由人决定分发**：先给愿意参与的少量目标读者审阅；本轮不发送、不发布。
6. **记录实际用途**：是否被引用、改变了范围/决策、避免了一次无效投入，或提出纠错。
7. **修订**：重要更正醒目标注；原始来源失效时保留已知边界，无法核实时降低结论强度。

## 情况分支

| 情况 | 处理 |
|---|---|
| 官网改定位 | 不直接判 pivot；查产品和官方说明，无证据记 positioning_change |
| 域名失效/repo archived | 不直接判商业失败；可能迁址、稳定归档、转手 |
| 收购后关闭产品 | 收购、服务退出、经济结果分开；不混进创业失败样本 |
| 当事人解释与公开数据冲突 | 并列呈现、写明冲突，不选择更戏剧性的版本 |
| 信息涉及私人生活或无关个人细节 | 删除；只保留专业决策所必需内容 |
| 删除/更正请求 | 复核公共利益与准确性，停止传播有争议段落，保留最少修订说明 |
| 支付链接消失 | 不能推断收入归零或关停；反链数据存在覆盖与幸存偏差 [L4] |
| 模型“总结出”未披露原因 | 删除推断性陈述，或清楚标为待检验假设，不能塞进事实字段 |
| 翻译改写改变原因强度 | 中英关键术语对照；保留“可能/自述/未知”，不能翻译成确定事实 |
| 高阅读、零使用反馈 | 只证明内容可传播，不证明决策价值或商业需求 |

## 时间与商业预算

前四类已有材料的二次整理，每两周一篇，最多 3h；若独立调查需超过 6h，先确认读者问题是否足够重要。不要为建立内容品牌同时开另一个大规模采集项目。

以 $50/h 计，3h 一篇内部成本 $150，一个月两篇为 $300，加分发和纠错尚未计。若没有读者使用、订阅或研究委托，不能把它当“低成本获客”。只有持续出现主动研究需求后，再检验一次性专题报告；订阅是更后面的选择。

## 四周观察与停止

- 第一周：列 5 个候选，只选与当前实际决策相关的 1 个；确认有原始证据。
- 第二周：完成 1 张案例卡及一个对照，找出一条会改变当前项目范围的判断。
- 第三周：若后续获授权，邀请最多 5 位目标读者使用并反馈；不把发送量当阅读量。
- 第四周：至少 2 个读者能描述具体使用场景，或 1 次实际决策改变，才继续内容实验。只是门槛假设，不是统计验证。
- 无法找到目标读者/原始证据，或连续 3 篇只有泛泛称赞：停止独立生产，改为内部决策备注。
- 发现严重事实错误：先更正再继续；不以发布频率抵消质量。

**结束判据：** 一份可信案例被用于具体决策，并吸收反馈；单纯阅读、点赞、订阅不是同一层级。商业成立还需独立付款证据。
