# 02 · 停服/成本变化 → 受影响确认 → 安全迁移

[返回总览](README.md) · Atlas 3/12/16；21 仅条件纳入。当前无已确认客户，先验证窗口和可迁移性。

## 为什么值得与哪里容易错

停服是明确的外部事件，但“有迁移期限”和“你能拿到迁移订单”之间仍有很远距离。免费用户可能直接放弃；企业可能已有供应商；预算与数据导出权限也可能不在抱怨者手中。

首轮聚焦 **Rails 应用的一个 API/AI provider/外围 SaaS 集成**，不做任意 SaaS 全栈迁移。第一类解决库或兼容层，第二类解决一个实际客户的切换；同一事件只设一个主负责人，防止两个 Radar 重复跟进。

付款方通常是工程负责人或产品负责人，使用者可能是开发者/运营，数据批准者可能另有其人。三者均要识别。没有当前受影响确认，只有“迁移观察卡”，不是销售线索。

## 已核查案例如何用

- OpenAI 官方迁移页已将 Assistants API 2026-08-26 停用写为过去事实。2026-10-25 不能再把它列为“即将停服”机会；可以用于历史迁移设计或已确认的遗留修复。[S05](sources.md)
- Glitch 2025-05-22 公告规定 2025-07-08 停止 hosting/profile，并给出当时的导出窗口。窗口已过，不能承诺今天仍能帮人导出。[S07](sources.md)
- Claude 文档区分模型状态和平台时间表。因此必须保存 provider、承载平台、区域、模型 ID；同名模型不能共享一个未经核实的截止日期。[S06](sources.md)

三者证明事件类型和误报风险，不证明本轮已有客户。历史案例应单列为 replay，不能计入今日线索。

## 触发到结果

1. **观察**：只跟踪少数官方 changelog、生命周期页、价格页；论坛只补充受影响证据。第一轮建议 5 个供应商，每周检查两次；近 30 天截止者再提高频率。
2. **规范事件**：存 announced_at、effective_at、export_deadline、时区、适用版本/套餐/地区、recommended_path、公告修订号。只有“将来某时”则截止日期 unknown。
3. **核对影响**：公开依赖只是线索；客户提供经授权的配置、调用量或场景后才确认。技术影响、商业损失分别写明。
4. **核对现有替代**：先查官方免费迁移工具与文档。若 30 分钟自助可完成且风险低，输出说明即可，不制造付费复杂度。
5. **评估和报价**：以字段/对象/语义差异、数据量、停机窗口、回滚和支持范围估算。先做小额付费诊断的假设测试，再决定是否全量项目。
6. **迁移演练**：只用授权脱敏样本或测试环境；验证全量数量、抽样内容、边界和业务链路。
7. **切换**：须另有客户授权和可执行回退；生产实施不在本轮文档任务范围。
8. **观察**：切换后第 1/7/30 天看错误、遗漏、费用和业务任务；记录验收、发票/付款及支持成本。

## 最小迁移包

| 交付 | 内容 | 验收 |
|---|---|---|
| 影响说明 | 具体停止的能力、日期、现有调用、谁确认 | 客户能指出哪条业务流程受影响；无影响也允许结案 |
| 兼容矩阵 | 旧对象/新对象、字段映射、鉴权、权限、时区、错误和速率限制 | 必需功能全部有替代/已批准的降级；unknown 不视为通过 |
| 数据演练 | 导出样本、总量、附件/关系、幂等键、异常清单 | 数量守恒；重要关系/附件可用；跳过项明确归档 |
| 行为回归 | 黄金用例、异步任务、回调、流式与工具调用等适用项 | 关键业务用例通过，模型迁移按质量评估而非文本字面相等 |
| 切换/回退 | 备份、冻结点、增量同步、路由开关、负责人 | 演练能恢复；旧服务已关时标明不可回退及替代恢复路径 |
| 运维交接 | 指标、费用预期、告警、支持结束日 | 客户接受并知道如何处理后续异常 |

不要同时写入两个系统而没有冲突策略。若是支付/订单等有副作用任务，优先只读比对、幂等和明确重放权限；“影子运行”不能产生两份真实业务动作。

## 情况分支

| 现象 | 处理 |
|---|---|
| 公告延期或撤回 | 保留旧版本，更新状态和优先级，通知已同意接收变更的人；不继续使用旧紧迫话术 |
| 只是 deprecated，没有停止日期 | 可规划升级，不能说已经不可用 |
| 只对新客户涨价，老客户 grandfathered | 排除未受影响客户；核实续约、seat、税与币种后再算差额 |
| 出口数据缺失、导出期限过了 | 先确认可恢复资产；不报价为完整迁移，不承诺找回无法访问的数据 |
| 无新服务地区/主体资格 | 停止该迁移路线；寻找合法可用替代，不能绕过资格限制 |
| 新服务便宜但额度、质量或留存不同 | 以真实工作负载计算 TCO，包含返工/质量损失；不能只比单价 |
| 客户接受停服、弃用功能 | 关闭线索，记录不迁移选择，避免强卖替代品 |
| 截止在 7 天内 | 先判断是否仍有安全演练时间；不确定时提供保全/降级方案或拒接 |
| 需要变更支付账户、KYC 或合同主体 | 与一般技术迁移分开，交由客户及相应专业人员确认，不作可行性保证 |
| 数据位于敏感系统 | 最小访问、脱敏/客户本地执行；先完成权限与存储约定再接触 |

## 商业与替代

出售的是“降低切换失败风险并完成可验收切换”，不是一份公共停服新闻。可能的三段范围：诊断 → 小样本演练 → 全量迁移与短期观察。只按已核实范围估价；超过数据量、对象种类、部署环境或支持期的部分另议。

示例预算：诊断 3h、映射/演练 6h、切换 3h、沟通/支持 4h，共 16h；内部 $50/h，加 $50 外部成本为 $850。假设报价 $1,200，尚余 $350 覆盖未计获客和返工。多一次数据异常就可能吃掉利润，故不可仅按“改几行 API”收费。这是算例，不是市场价。

触达先从已有应用团队、明确公开寻求迁移帮助者或维护者转介开始。任何发信、留言和报价发送需用户另行决定；本轮只准备资料。

## 四周验证与停止

- 第 1 周：最多研究 10 个官方事件，先剔除过期、不适用、无数据出口者。
- 第 2 周：对剩余候选争取 3 个受影响场景确认（须后续授权接触）；0 个确认则不做通用迁移工具。
- 第 3 周：一份限定范围的兼容矩阵和演练方案，至少一个用户愿提供授权样本才进实现。
- 第 4 周：目标是 1 个付费诊断或明确试点承诺；二者分别记录，承诺不记作收入。
- 连续 10 个事件都无可接触主体：暂停采集，重选渠道；有主体但不愿提供数据/预算：修正服务范围，不提高新闻抓取频率。
- 无法恢复、重要功能无替代、不可满足权限、验收风险超出能力：拒接或转介。

**结束判据：** 迁移在约定范围完成且可观察，或者明确判定不迁移并记录原因。只有公告和替代清单不算闭环。
